# Oh-My-LOAM GUI 开发目录说明

本目录用于存放 Oh-My-LOAM 的 GUI 层和 SlamRunner 调度控制层开发内容。现有命令行 loam 核心层已经通过测试，后续开发重点是给核心程序包装一个 WinForms 人机交互外壳。

## 目录结构

```text
gui/
  README.md
  SlamGui/
  SlamRunner/
  runtime/
    core/
    output/
    logs/
  docs/
  scripts/
  tests/
  samples/
  third_party/
  release/
```

## 各目录用途

### SlamGui/

存放 GUI 层项目源码。

建议内容：

- VS2019 C++/CLI WinForms 可执行程序项目。
- 主窗体文件，例如 `FormMain.h`、`FormMain.cpp`。
- GUI 入口文件，例如 `Main.cpp`。
- 中文界面控件、按钮事件、日志窗口、进度条和状态标签代码。

边界要求：

- GUI 只负责选文件、点按钮、显示状态和日志。
- GUI 不直接读取或写入点云内容。
- GUI 不直接调用 loam 算法和 PCL 点云处理接口。

### SlamRunner/

存放 SlamRunner 调度控制层项目源码。

建议内容：

- VS2019 C++/CLI 类库项目。
- `SlamRunnerService` 托管类。
- `SlamRunRequest`、`SlamRunState` 等接口类型。
- `loadPointCloud(pcd)`、`loadConfig(yaml)`、`run()`、`Stop()`、`saveResult()` 等接口实现。
- loam CLI 子进程启动、停止、日志捕获、进度统计和资源释放逻辑。

边界要求：

- `SlamRunner` 是 GUI 与 loam 核心之间的唯一调度控制层。
- 每个 `SlamRunnerService` 实例只允许运行一次。
- 运行完成、失败或停止后必须释放 loam 子进程、后台线程和相关句柄。

### runtime/core/

存放本地开发和调试时使用的完整 loam 核心运行资产。

应从以下目录复制完整内容：

```text
C:\Users\a2676\Documents\oh-my-loam\oh_my_loam-main\build\win10_noros_src\dist\oh_my_loam_debug_x64_v2
```

该目录应包含：

- loam 核心 exe。
- config 配置文件。
- PCL、yaml-cpp、g3log 等运行依赖 DLL。
- loam CLI 运行所需的全部文件。

注意：

- 不要从临时 CMake build 目录零散拼依赖。
- GUI 调试时优先从此目录启动核心 exe。
- 最终发布包也应以该 dist 目录作为核心资产来源。

### runtime/output/

存放本地调试运行生成的结果文件。

建议规则：

- 每次运行创建日期时间戳子目录，例如 `20260623_143000/`。
- 地图文件命名为 `map_yyyyMMdd_HHmmss.pcd`。
- 轨迹文件命名为 `trajectory_yyyyMMdd_HHmmss.txt`。

### runtime/logs/

存放本地调试运行生成的日志文件。

建议规则：

- 日志文件命名为 `log_yyyyMMdd_HHmmss.txt`。
- GUI 日志和 loam 核心 stdout/stderr 日志可以分开保存，也可以在 V1 阶段先合并保存。

### docs/

存放 GUI 开发相关补充文档。

建议内容：

- 界面草图。
- 控件命名说明。
- SlamRunner 接口变更记录。
- 手工测试记录。
- 后续用户使用说明草稿。

项目根目录中的 `GUI开发需求文档.md` 和 `GUI开发Plan与Todolist.md` 仍作为主需求和主计划文档。

### scripts/

存放开发、测试、打包辅助脚本。

建议内容：

- `package_gui.ps1`：复制 GUI Release 输出、Runner DLL 和 loam 核心 dist 文件，生成发布目录或 zip 包。
- `check_runtime.ps1`：检查核心 exe、config、DLL 是否齐全。
- `clean_runtime_output.ps1`：清理本地调试输出和日志。

### tests/

存放 GUI 包装层的测试资料和测试说明。

建议内容：

- smoke test 步骤。
- 停止按钮测试记录。
- 缺少 exe、缺少 config、空 PCD 目录等异常用例。
- 小规模测试数据路径说明。

注意：

- 大体积点云数据不建议直接放入源码仓库。
- 如果需要样例数据，优先放入 `samples/`，并在 README 中注明体积和来源。

### samples/

存放可选的小规模样例数据或样例数据说明。

建议内容：

- 小规模 PCD 序列。
- 示例 YAML 配置。
- 样例数据来源说明。

注意：

- 该目录只用于快速验证 GUI 启动和调度流程。
- 大数据集建议放在项目外部，通过 GUI 选择目录导入。

### third_party/

存放 GUI 层额外需要的第三方依赖。

当前建议：

- V1 阶段尽量保持为空。
- WinForms、C++/CLI 和 .NET Framework 依赖由 VS2019/.NET 运行环境提供。
- loam 核心依赖不要重复放在这里，应随完整核心 dist 放入 `runtime/core/` 或发布包 `core/`。

### release/

存放最终打包发布产物。

建议发布结构：

```text
release/
  OhMyLoamGui/
    SlamGui.exe
    SlamRunner.dll
    core/
    docs/
    README.txt
    CHANGELOG.txt
    THIRD_PARTY_LICENSES.txt
```

注意：

- `release/` 中内容应由打包脚本生成。
- 不建议手动维护 release 目录中的文件。
- 发布包中不应包含开发机临时路径或不必要的编译中间文件。

## 开发顺序建议

1. 在 `SlamRunner/` 中先实现最小可用的 loam CLI 启动、日志捕获和停止控制。
2. 在 `SlamGui/` 中实现中文 WinForms 主窗体。
3. 将 `runtime/core/` 指向或复制完整 loam dist 核心资产。
4. 跑通 GUI 选择 PCD 目录、选择 YAML、启动、日志显示、停止的 V1 闭环。
5. 再进入 V2 的输出命名、异常处理、细节优化。
6. 最后进入 V3 的发布打包和干净环境验证。
